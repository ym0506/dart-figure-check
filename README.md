# dart-figure-check

사업보고서(DART)의 재무 표에서 LLM이 옮겨 적은 숫자를 받기 전에 무엇을 확인해야 하는지 재 보는 작은 실험입니다.

앞선 프로젝트(미국 10-K로 투자안을 심사하는 에이전트)에서 인용이 원문에 글자 그대로 있고 그 안에 같은 숫자가 있는지만 보는 검사는
**같은 인용 안의 다른 숫자를 고른 오류**를 거르지 못했습니다. 재무 표의 한 행에는 당기와 전기 숫자가 나란히 있어서 이 오류가 가장 흔하게
생길 자리입니다. 이 실험은 그 구멍을 한국 공시로 재현하고 표 칸 위치 확인으로 막히는지 봅니다.

## 무엇을 재나

- **정답**: 사람이나 AI가 적은 정답표 대신 DART 공식 재무 데이터(`fnlttSinglAcntAll`, 연결)의 당기·전기 금액(원)을 씁니다.
- **표본**: 2026년 3월에 접수된 유가증권시장 사업보고서(2025 회계연도, 정정 제외)를 접수번호 순으로 보며 대상 계정 6개
  (매출액, 영업이익, 당기순이익, 자산총계, 부채총계, 자본총계)가 공식 데이터에 모두 있는 회사를 앞에서부터 10곳.
- **원문 읽기**: `document.xml`의 본문 XML을 표준 라이브러리로 관대하게 읽고 표마다 병합 칸을 풀어 칸 위치(T표R행)를 유지합니다.
  단위는 표 앞의 '(단위 : 백만원)' 문구로, 당기·전기 열은 머리글의 기수나 연도로 코드가 정합니다.
- **검사 두 가지**
  - P1 글자와 숫자 대조: 인용이 원문 줄에 그대로 있고 인용 안에 같은 숫자가 있으면 받습니다. 값과 단위는 LLM이 말한 대로 씁니다.
  - P2 표 칸 확인 추가: LLM이 가리킨 표가 연결재무제표인지, 그 행 이름이 계정과 맞는지, 그 행의 해당 기간 열 숫자가 LLM 값과 같은지
    확인하고 최종 값은 코드가 칸에서 읽은 숫자와 표 단위로 계산합니다.
- **LLM 방식 두 가지**(Claude Haiku 5.5): 요약재무정보와 연결재무제표 표를 통째로 주기, '재무에 관한 사항' 전체를 행 단위로 쪼개
  BM25 상위 5행만 주기.
- **청킹 비교**(API 없음): 행 단위 덩어리와 1,000자 고정 길이 덩어리에서 정답 행이 BM25 상위 k개 안에 드는 비율.
- **오류 주입**(API 없음): 맞게 받은 답에 기간 바꿔치기, 연결 대신 별도, 단위 착오, 부호 빠짐, 숫자 한 자리 오류를 넣고
  P1과 P2가 틀린 값을 몇 번 통과시키는지 셉니다.

## 실행

```bash
python3 -m venv .venv && .venv/bin/pip install opendart-py==0.1.0 anthropic pytest
.venv/bin/python -m pytest -q
.venv/bin/python -m dartcheck.fetch 10      # DART 키: ~/.config/opendart/.env 의 DART_API_KEY
.venv/bin/python -m dartcheck.run parse
.venv/bin/python -m dartcheck.run recall
.venv/bin/python -m dartcheck.run llm       # Anthropic 키 필요
.venv/bin/python -m dartcheck.run score
```

내려받은 공시 원문은 `data/raw/`에만 두고 저장소에 넣지 않습니다. DART 호출은 [opendart-py](https://github.com/TreasurerSquad/opendart-py)를 씁니다.

## 결과 (2026-11-16)

표본 10곳: 진양산업, 대한유화, 국도화학, 현대모비스, 케이씨씨, 삼성전자, 하이스틸, 유니드, 삼성SDI, 제일기획.
같은 규칙으로 앞에서 만난 4곳(진양화학, 인천도시가스, 미원화학, 롯데리츠)은 연결 재무 데이터가 없어 빠졌습니다(`data/raw/sample.json`, 저장소 밖).

### 원문 읽기

정답 120칸(10곳 × 계정 6개 × 당기·전기)을 모두 원문 표에서 코드로 찾았습니다. 단위는 원(8곳)과 백만원(2곳)이 섞여 있었습니다.

### 오류 주입 (`python -m dartcheck.run inject`, 결과 `results/inject_gold.json`)

올바른 답 120개(정답 칸에서 코드로 만든 인용, 값, 단위)를 두 검사에 넣으면 둘 다 120개를 모두 받습니다.
여기에 오류를 하나씩 넣고 틀린 값을 몇 번 통과시키는지 셌습니다.

| 넣은 오류 | 넣은 수 | P1 인용과 숫자 대조 | P2 표 칸 확인까지 |
|---|---|---|---|
| 당기와 전기 바꿔치기 | 120 | 120 통과 | 0 |
| 연결 대신 별도재무제표 값 | 120 | 120 통과 | 0 |
| 같은 표의 다른 행 | 120 | 119 통과 | 0 |
| 단위를 잘못 적음 | 120 | 120 통과 | 0 |
| 숫자 한 자리 틀림 | 120 | 0 | 0 |
| 음수 부호 빠짐 | 7 | 0 (부호를 무시하고 비교하면 7) | 0 |

P2가 겨냥한 오류들이라 P2의 0보다 P1이 이 오류들을 거의 전부 통과시킨다는 점과 P2가 올바른 답을 하나도 거부하지 않았다는 점이 결과입니다.
'같은 표의 다른 행'에서 1건은 옆 행 값이 정답과 같아 틀린 값이 아니었습니다.

**P2에서 찾은 구멍**: 처음 만든 P2는 행 이름을 부분 문자열로 비교해서 '매출원가'를 매출액으로, '부채와자본총계'와 '부채및자본총계'를 자본총계로,
'지배기업의 소유주에게 귀속되는 당기순이익(손실)'을 당기순이익으로 받았습니다(다른 행 오류 120건 중 29건 통과).
주석 번호를 뗀 이름이 계정별 목록과 정확히 같아야 받게 바꾼 뒤 0건이 됐고 올바른 답 120개는 그대로 모두 받습니다. 비교용으로 `label_ok(strict=False)`를 남겼습니다.

### 검색 비교 (`python -m dartcheck.run recall`, 결과 `results/recall.json`)

정답 행(요약재무정보나 연결재무제표에서 행 이름이 맞고 당기 칸이 공식 금액과 같은 행)이 BM25 상위 k개 덩어리 안에 든 계정 수(전체 60).

| 청킹 | 상위 1 | 상위 3 | 상위 5 | 상위 10 |
|---|---|---|---|---|
| 행 단위, '재무에 관한 사항' 전체 | 17 | 28 | 31 | 31 |
| 1,000자 고정(200자 겹침), 전체 | 23 | 34 | 36 | 51 |
| 행 단위, 요약재무정보와 연결재무제표 섹션만 | 34 | 36 | 52 | 60 |

'재무에 관한 사항'에는 회사마다 표가 300~1,600개 있고 주석과 별도재무제표에도 '매출액' 행이 많습니다. 글자 검색만으로는 연결 본표를 찾기 어렵고
DART 문서의 표준 섹션 제목으로 먼저 거르는 것이 가장 효과가 컸습니다.

### 한계

- 오류 주입은 검사기를 시험한 것입니다. LLM이 실제로 이런 오류를 얼마나 자주 내는지는 아래 LLM 실행으로 따로 봐야 합니다.
- 표본은 2025 회계연도 유가증권시장 10곳, 계정 6개뿐입니다. 금융회사(은행, 보험)는 재무제표 구조가 달라 규칙상 빠집니다.
- 기간 열은 머리글의 기수나 연도로 정합니다. 머리글에 기간 표시가 없는 표는 P2가 받지 않습니다.
